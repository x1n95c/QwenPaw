# 天气播报

## 什么时候用

- 拿到了 `wttr.in` 的 JSON（`?format=j1`），需要写成给人看的播报
- 需要基于天气给出穿衣、带伞、出行建议

## 不应使用

- 还没取到数据（先取，再播报）
- 用户问的是历史气候或长期趋势——`j1` 只有当天与未来两天

## 播报结构（必须遵守）

```
<城市> 今天 <天气> <最低>~<最高>℃（体感 <feels_like>℃）

- 降水：<有无 / 时段>
- 风：<风力>
- 建议：<穿衣 / 带伞 / 出行，最多两条>
```

## 口径

1. **只说影响决策的信息**。湿度、气压、能见度这类除非异常（如能见度低、
   风力大）否则不要出现——这是每天都会推送的播报，塞满数据等于没人看。
2. **温度用整数**，`wttr.in` 的小数没有意义。
3. **建议要具体**。「注意保暖」是废话；「早晚 8℃ 上下，外套别脱」才有用。
4. 有降水时必须给出**时段**（`hourly` 里 `chanceofrain` 高的时段），
   而不是只说「有雨」。
5. **拿不到数据就直说**。`wttr.in` 会限流或超时，此时回一句
   「天气数据获取失败」，不要用常识编一个天气。
6. 城市名用 JSON 里 `nearest_area` 的值回显一次，让用户能发现定位错了。

## 关于城市

`batch/weather.json` 里是 `${args.city}`：

- 传具体城市名（`Beijing` / `上海` / `Tokyo`）查该城市
- **传空字符串** `""` 则 URL 变成 `https://wttr.in/?format=j1`，
  wttr.in 会按出口 IP 自动定位——不想配城市时用这个

## 依赖

需要 `curl`（macOS / Linux 自带；Windows 10 1803+ 自带 `curl.exe`）
以及能访问 `wttr.in` 的网络。
