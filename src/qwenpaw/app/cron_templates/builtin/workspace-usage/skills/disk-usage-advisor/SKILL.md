# 磁盘占用巡检与判读

## 什么时候用

- 需要巡检磁盘余量、找出占用最大的目录
- 需要给出「删什么、能腾出多少」的建议

## 不应使用

- 用户只是问「怎么查看磁盘占用」这类操作方法问题
- 目标目录还不明确

---

## 第一步：按平台采集

采集命令**因系统而异**。先看系统提示里的 Platform（`darwin` / `linux` / `win32`），
再选对应的批处理脚本。任务 prompt 会给出模板目录，脚本在其 `batch/` 下：

| 平台 | 脚本 | 用的命令 |
|---|---|---|
| macOS（`darwin`）、Linux | `batch/scan-unix.json` | `df -h`、`du -sh` |
| Windows（`win32`） | `batch/scan-windows.json` | `Get-PSDrive`、`Get-ChildItem` |

调用方式：

```
run_tool_batch(
  file_path="<模板目录>/batch/scan-unix.json",     # Windows 换成 scan-windows.json
  args={"path": "<agent workspace 目录>"}
)
```

`args.path` 填你自己的 workspace 目录（系统提示里的 Working directory）。
**不要写死** `~/.qwenpaw/...`：这个位置可以被 `QWENPAW_WORKING_DIR` 改掉。

### 为什么不能用同一条命令

- `df` / `du` 在 Windows 上不存在
- PowerShell 的 `Get-PSDrive` / `Get-ChildItem` 在 macOS 默认没有

所以是两个脚本、一份判读逻辑。**如果选错脚本**，命令会直接报
`command not found` 或「不是内部或外部命令」—— 看到这类报错就换另一个脚本重试。

### 两个脚本的输出格式

都是两段，含义一致，便于统一判读：

1. 每个挂载点/盘符的：已用、可用、使用率百分比
2. `args.path` 下按大小降序的前 10 个子目录

---

## 第二步：按阈值判读

| 使用率 | 动作 |
|---|---|
| < 85% | **只回一句「磁盘正常」**，不要列举目录、不要给建议 |
| 85% – 94% | 提醒 + 列出占用最大的 5 个目录 + 清理建议 |
| ≥ 95% | 标记为紧急，另外指出哪些能立刻安全删除 |

**这条纪律的意义**：定时任务每天都会跑。如果每天都输出一堆目录列表，
用户很快就会无视它，真出问题时也看不见。低于阈值就保持安静。

---

## 第三步：汇报（仅超过阈值时）

```
⚠️ <挂载点/盘符> 已用 <百分比>（剩余 <可用量>）

占用最大：
1. <目录> — <大小>
2. …

建议：
- <具体动作>（预计腾出 <大小>）
```

## 判读要点

1. **只看数据说话**。因权限被跳过的目录不要算进结论，必要时说明
   「部分目录无权限读取」（两个脚本都忽略了权限错误，所以不会报错，只会少统计）。
2. **区分「大」和「可删」**。缓存、日志、临时产物可以建议清理；
   `sessions`、`checkpoints`、`jobs.json` 这类是状态数据，**不要建议删除**，
   最多建议归档。
3. 能给出量化收益就给（「清掉 X 可腾出 1.2G」），估不出来就别编。
4. 多个挂载点/盘符时，只对越过阈值的那个展开；其余一句话带过。
5. **单位不要混**。Unix 脚本给的是 `Gi`/`Mi`，Windows 脚本给的是 `GB`/`MB`，
   照抄脚本的输出单位，不要自己换算。
6. 不确定某目录用途时直说不确定，不要猜测后建议删除。
